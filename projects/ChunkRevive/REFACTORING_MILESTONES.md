## 本輪 MySQL 與停機驗收（2026-11-07）

- 本機 MySQL 使用隨機 `chunkrevive_it_*` 臨時 schema；測試先建立舊版 `operations` 表，再由 repository 執行 schema migration，驗證標記新增／重複新增／讀取／刪除、操作新增／無變更更新／重複主鍵失敗。測試透過 `KILL CONNECTION` 中斷實際伺服器 session，確認故障時讀取回報 `SQLException`，建立新連線後既有操作資料仍可讀取，最後刪除臨時 schema。`MySqlPersistenceIntegrationTest` 實際連線驗收通過。
- JDBC 停機採有界策略：停用期間最多等 5 秒排空操作歷史寫入，之後在 virtual thread 背景等待共用 JDBC 鎖並關閉資料庫；停機執行緒不等待底層 JDBC 呼叫或 `Connection.close()`。在途 I/O 未返回前，連線會留在背景等待，完成或失敗會記錄結果。`OperationPersistenceTest` 驗證背景 close 被刻意卡住時呼叫端仍返回，以及 close 仍會等待共用交易鎖；兩項測試通過。
- 本輪專項測試通過；根專案 `check` 通過 43 個工作。Eclipse JDT formatter 套用後，格式檢查與差異空白檢查通過。

## M1：資料庫相容性（主要 MySQL 路徑已完成真實驗收）

- 已處理 SQLite／MySQL 建表與標記寫入語法、MySQL JDBC 驅動封裝，以及 `useAffectedRows=true` 下無變更更新的結果判定；已加入 SQLite 回歸和模擬初始化測試。
- 本輪 FreshLib SQL helper 複查：MySQL／PostgreSQL 的 `executeNonQuery` 原先建立後未關閉 `Statement`，現以 try-with-resources 關閉；SQLite 繼承 MySQL 實作一併修正。原始 `executeQuery(String)` 也未關閉擁有的 statement；新增具型別 `ResultSetHandler<T>` overload，以 try-with-resources 管理 result set 與 statement，並將舊 raw-result-set overload 標記為 deprecated。為避免破壞第三方 `Database` 實作，新 overload 是會關閉 result set 的 default method；內建 MySQL／PostgreSQL 實作再覆寫以一併關閉 statement。測試涵蓋舊式介面實作、兩種 driver 的 callback 成功及失敗清理；真實 MySQL 驗收仍未完成。
- 本輪 FreshLib JDBC 連線狀態複查：MySQL／PostgreSQL `isConnected()` 原先只判斷 connection 欄位非 null；若使用者已關閉 JDBC handle，仍回報連線中，後續 `connect()` 可能略過重連。現在依 `Connection.isClosed()` 回報，狀態查詢發生 `SQLException` 時視為未連線；`close()` 仍會清理由外部關閉但欄位保留的 connection。`DatabaseStatementTest` 新增兩種 driver 的關閉／狀態查詢失敗測試，FreshLib 專項通過；根專案 `check` 通過 43 個工作（6 執行、37 最新）、JDT 格式檢查與 `git diff --check` 通過。真實 MySQL 驗收仍待專用帳號。
- 本輪 FreshLib 時長解析複查：`FreshDuration.parse` 的單位乘法及多段累加原先可能溢位成負值並被當作「永不」；現以精確乘加在解析邊界拒絕超出 `long` 毫秒範圍的輸入，並將 token pattern 編譯為共用常數。新增上限、乘法溢位與累加溢位測試。
- 本輪 FreshLib 檔案工具複查：`readResource` 原先依賴 `InputStream.available()` 配單次讀取，可能得到不完整資源；`saveFile` 原先直接拼接目的路徑、未關閉來源串流。改用 `readAllBytes`、完整管理串流，並拒絕解析後離開插件資料目錄的目的路徑；新增完整讀取、保留既有檔案及阻擋 `..` 逃逸測試。檔名搜尋改用 `Locale.ROOT`，避免土耳其語系改變大小寫結果，並新增還原預設語系的回歸測試。
- 本輪複查：檢視 `PersistenceRepository`、各 SQL store、MySQL schema 轉換與新增操作關聯寫入；未發現已確認的行為回歸。SQLite 寫入回滾／遷移／重啟測試及模擬 MySQL 初始化測試重跑通過；真實 MySQL 行為仍未驗證。
- 本輪封裝驗證：重新建置 FreshLib `shadowJar`，確認產物包含 MySQL Connector/J 類別和 `META-INF/services/java.sql.Driver`，並以產物 classpath 成功載入 `com.mysql.cj.jdbc.Driver`。這確認驅動有打包且可載入；實際 FreshLib 插件 classloader 與 MySQL 連線仍待伺服器／資料庫驗收。
- 環境盤點：本輪確認本機 `MySQL96` 服務仍在執行；目前工作階段未提供 MySQL CLI 或資料庫連線環境變數。先前專案預設的 root 空密碼登入被伺服器拒絕；Docker CLI 已安裝但 Engine 未啟動，目前帳號無法啟動 Docker Desktop service，因此不能以臨時 MySQL container 繞過現有帳號限制。取得專用測試帳號或可啟動的隔離 MySQL 環境後再執行真實驗收。
- 尚待：在 MySQL 驗證資料表建立、既有欄位遷移、主要讀寫、重複資料回報、無效或超長資料的錯誤回報、無變更更新，以及伺服器內 FreshLib 插件 classloader 的 driver 載入。
- 完成條件：SQLite 回歸測試和真實 MySQL 驗收均通過；失敗輸入不會回報成功，遷移不破壞既有資料。
